# Автоматическая расстановка пробелов в слитно написанных русских текстах с использованием динамического программирования, частотного словаря, SentencePiece и морфемной классификации на основе BERT.
Проект предназначен для восстановления пробелов в текстах, где они были утеряны (например, при OCR, парсинге или опечатках).   
Используется комбинированный подход: сначала применяется сегментация на основе динамического программирования, затем уточнение с помощью морфемной модели на BERT.  
## Быстрый старт
1. Клонируйте репозиторий  
git clone https://github.com/necoarcreator/samplesML/Spacer.git  
cd Spacer  
2. Установите зависимости  
pip install -r requirements.txt  
3. Запуск  
from main import run_pipe, transform_data  
run_pipe() # просто возвращает строки-результаты, не преобразует датасет  
transform_data() # не возвращает сами переделанные строки, но добавляет столбец к датасету с позициями пробелов

## Принцип работы пайплайна  
1. DPSpacer — сегментирует текст с помощью динамического программирования, опираясь на частотный словарь.  
2. WordValidator (на основе BERT) — проверяет, является ли слово «морфологически правильным» (имеет 1 корень, логичную структуру морфем).  
3. GreedySpacer — вторая попытка: жадная сегментация по максимальному совпадению, если BERT не уверен.
4. SentencePiece + очистка от "##" - "последний шанс" улучшить читаемость текста, если BERT всё ещё не уверен.
5. Комбинированный пайплайн — сначала сегментируем DP → проверяем BERT → если слово «плохое» — сегментируем жадным алгоритмом → проверяем снова → fallback на жадный sentencepiece из rubert.  
## Слабые стороны проекта и возможные улучшения
Неразмеченные данные => невозможно без ручной разметки / обращения к LLM сгенерировать датасет для обучения с учителем.
Кроме того, с ходу сложно придумать и подход для реализации reinforcement learning (за какие действия давать награду). 
Мало предобученных моделей для восстановления пробелов: максимум, что я нашёл - это [ruT5-paraphraser](https://huggingface.co/fyaronskiy/ruT5-large-paraphraser). Но он для задачи не подходит.

При менее строгих ограничениях на реализацию, можно было бы создать синтетический датасет и дообучить rubert на  подобную задачу LM.  
Имеющиеся модели слишком жадны, вознаграждают короткие слова и не не всегда знают домен (например, xboxone).  
Кроме того, эвристика, которая реализована с сегментацией морфем BERT'ом, также неидеальна и, например, считает   сложные слова не до конца разбитыми на морфемы. А ещё она нечувствительна к латинице.  

Отсюда низкое качество как на трейне, так и на тесте.
